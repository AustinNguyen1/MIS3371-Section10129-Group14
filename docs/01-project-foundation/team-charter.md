## Team Norms

- Team members should respond within 24 hours when possible and no later than 48 hours.
- If a team member is unable to complete their assigned part, they should inform the team at least 48 hours before the due date unless an emergency occurs.
- Team members should communicate issues or blockers early so the group has time to respond.
- Roles represent primary ownership, but team members may help with other areas when needed.

## Communication

- Communication between team members will be done through Messages.
- Important project decisions are discussed in the group Messages chat and then recorded in the repository's [decision log](../decisions.md) so they can be reviewed and defended later.
- If an issue arises that no team member can solve and it significantly affects the project, the Team Leader should reach out to the TA for guidance.

## Git Workflow

- Pull before starting to make sure you have the latest version.
- Use clear and meaningful commit messages.
- Use focused branches for larger changes when appropriate.
- Review changes before merging.
- For larger changes, it is preferred to consult another teammate before merging into the main branch.

## Accountability

- Team members are responsible for completing their assigned tasks.
- Each member should understand and be able to explain the code or work they contributed.
- If assistance is needed, members should understand the reasoning and logic behind the solution so they can explain it and avoid repeating the same issue.
- Every member should be able to explain important project decisions during individual code defense.
